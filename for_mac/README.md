# 画面キャプチャツール (macOS版) の使い方

本ツールは、試験中の画面をバックグラウンドで定期的に記録し、提出用 ZIP を作成するための macOS 版ツールです。

現在の実運用版は次の場所にあります。

- `for_mac/配布用formac/CaptureSystem`

主な入口は次の 3 つです。

- 開始: `start.sh`
- 状況確認: `Check.app`
- 終了 / 提出: `bin/finish.sh`

関連ドキュメントは `for_mac/docs` にまとめています。

---

## 1. 事前に知っておくこと

- 試験開始前は **オフライン必須** です
- 学籍番号の入力が必要です
- 画面収録権限の付与が必要です
- 証拠画像はバックグラウンドで自動撮影されます
- 提出 ZIP は、原則として
  `~/Desktop/{学籍番号}_{YYYYMMDD}`
  に保存されます
- デスクトップに保存できない場合は
  `~/Downloads/{学籍番号}_{YYYYMMDD}`
  が使われます

---

## 2. `swift` について

この mac 版は、端末によって `swift` コマンドの利用可否が異なる可能性があります。

- `swift` が使える端末:
  - 常時最前面バーが表示されます
  - リッチな警告ロック画面が表示されます
- `swift` が使えない端末:
  - 常時バーは表示されません
  - 警告時は簡易ダイアログ型ロック画面へ自動フォールバックします

どちらの場合でも、キャプチャ、開始前オフライン確認、試験中ネットワーク監視、提出拒否、USB + TA PIN による解除の最低限機能は継続する想定です。

確認したい場合は、ターミナルで次を実行してください。

```sh
swift --version
```

---

## 3. 試験を開始する

1. `CaptureSystem/start.sh` を実行します
2. 学籍番号を入力します
3. 画面の案内に従って、必要なら画面収録権限を付与します
4. オフライン確認を通過すると、撮影が開始されます

補足:

- Wi-Fi が ON のままだと開始できません
- 当日の未提出データがあれば、自動で再開案内が出ます
- 提出済み ZIP が見つかれば、復元再開案内が出ます

---

## 4. 試験中の確認方法

### 常時バーで確認する

`swift` が使える端末では、画面上部に次の情報が表示されます。

- 学籍番号
- 撮影枚数
- 現在時刻

### `Check.app` で確認する

必要に応じて `Check.app` を起動すると、現在の状態を確認できます。

- `正常に稼働中`
- `停止中`

特に `swift` が使えない端末では、常時バーが出ないため、稼働確認は `Check.app` がわかりやすいです。

---

## 5. 試験中の注意

- 試験中は Wi-Fi を ON にしないでください
- ネット接続が検出されると、警告状態になります
- 警告状態では提出できません
- TA の指示があるまで操作しないでください

---

## 6. ネット接続が検出された場合

ネット接続が検出されると、次の動作が行われます。

- `network_warning.log` が記録される
- ロック画面または簡易警告ダイアログが表示される
- 提出処理が拒否される

### TA による解除

- TA用USB + TA PIN で解除します
- **解除前に Wi-Fi を OFF にする必要があります**
- Wi-Fi が ON のままでは解除できません
- 現在の運用では、TA PIN のハッシュはシステム本体ではなく **TA用USB側** に持たせます

---

## 7. 試験を終了して提出する

1. TA / 試験監督の指示に従い `CaptureSystem/bin/finish.sh` を実行します
2. 記録が停止し、提出用 ZIP が作成されます
3. 作成された ZIP を指定の方法で提出します

ZIP 名は次の形式です。

```text
{学籍番号}_{YYYYMMDD_HHMMSS}.zip
```

---

## 8. ファイル命名規則

- 保存フォルダ:
  `{学籍番号}_{YYYYMMDD}`
- 画像名:
  `{学籍番号}_{連番3桁}_{HHmmss}.jpg`
- ZIP 名:
  `{学籍番号}_{YYYYMMDD_HHMMSS}.zip`

---

## 9. トラブル時

### 画面収録の許可が通らない

- 「システム設定」→「プライバシーとセキュリティ」→「画面収録」を開きます
- 実行に使っているターミナルアプリ
  例: `Terminal.app`, `iTerm`
  に権限を付与してください

### `swift` が使えない

- 常時バーは表示されません
- 警告時は簡易ダイアログに切り替わります
- ただし、最低限の試験運用は継続可能です

### 一度終了したが、続きから再開したい

- 当日の未提出データがあれば、自動で再開案内が出ます
- 当日の提出済み ZIP が見つかれば、復元再開案内が出ます

### ネット検知後に解除できない

次を確認してください。

- Wi-Fi が OFF になっているか
- TA 用USBが接続されているか
- TA PIN が正しいか
- `CaptureSystem/.ta_unlock_policy` と USB 内 `ta_unlock.key` の `challenge_id` が一致しているか
- `ta_unlock.key` が旧形式ではなく、`unlock_key` と `pin_hash` を両方含んでいるか

### ロック解除の応急処置

通常は、TA用USB + TA PIN で解除してください。

ただし、USB認識不良や UI 不具合などで通常解除できない場合は、
**緊急用の応急処置**として `LOCK_ACTIVE.flag` を削除して復旧できます。

対象ファイル例:

- `~/Desktop/{学籍番号}_{YYYYMMDD}/{実行中フォルダ}/LOCK_ACTIVE.flag`

補足:

- この方法は **通常運用では使わず、最後の手段** としてください
- `LOCK_ACTIVE.flag` が削除されると、ロック画面は解除状態になります
- 応急処置後は、必要に応じて `network_warning.log` も確認してください

---

## 10. 補足

- 現時点では **マルチモニタ全体キャプチャは未対応** です
- 証明書ベースの TA解除は未対応です
- USB解除を使う場合は、配布前に次を準備します
  - `CaptureSystem/.ta_unlock_policy`
  - TA用USB内の `ta_unlock.key`
- `.ta_unlock_policy` には `key_hash` のみを置き、TA入力用の `pin_hash` は USB 側 `ta_unlock.key` に持たせます
- 実ファイルの `.ta_unlock_policy` と `ta_unlock.key` は `.gitignore` 対象です
- Git には雛形ファイルのみ置きます
  - `for_mac/配布用formac/CaptureSystem/.ta_unlock_policy.example`
  - `for_mac/ta_unlock.key.example`
- 補助スクリプト:
  `for_mac/create_usb_unlock_materials.sh`
  で USB解除用ファイルを生成できます
- 試験ごとに本体一式を手編集しないよう、実運用では USB 側の `ta_unlock.key` に解除用情報を持たせる方針です
